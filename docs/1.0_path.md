# Roadmap and API compatibility

PureMacro has passed 1.0. This page replaces the old pre-1.0 checklist;
its URL is retained for existing links. As of 2026-10-29, **6.0.1 is the
published release** and **6.1.0 is under development**. Source tags 5.8.0,
5.9.0 and 6.0.0 were not published to PyPI. Consult the
[changelog](https://github.com/jalonso1979/puremacro/blob/main/CHANGELOG.md)
and the version returned by `puremacro.__version__` when reproducing a result.

## Development priorities

1. The 6.1 development source includes the GMM engine, asset-pricing core,
   sovereign fiscal block and bilingual policy briefs. Release checks now cover
   supported platforms, Python 3.11 typing and examples from an installed wheel.
2. The published one-asset HANK **general equilibrium** now passes independent
   nonlinear and grid/horizon checks; see the [benchmark](hank_equilibrium.md).
   Extend this foundation to household incidence and observed-data workflows.
3. The baseline short-term Arellano grid study is complete. Independent
   small-grid equations now check long-term debt, restructuring and the
   illustrative collateral planner; see [extension validation](sovereign_extensions_validation.md).
   Sensitive reentry/persistence scenarios still require separate grid evidence.
   Published extension moments and a full competitive collateral model remain
   outside the validated scope.
4. Done in the 6.1 development source: independently check and explain the
   tariff brief's positive consumption EV, including investment, other final uses
   and the resource balance. See [tariff validation](tariff_validation.md).

Completed development milestones do not establish every model or calibration,
or promise shipment in a particular release. The
[research reliability guide](research_reliability.md) records the current
boundary between replication evidence, internal checks and demonstrations.

## Compatibility policy

Public exports and result-class field names are recorded in
`tests/fixtures/public_api_snapshot.json`. Gate 3 requires an intentional,
reviewed snapshot update for additions and other surface changes. The snapshot
checks names, not numerical correctness, function signatures or semantic
compatibility; those require tests and review.

For the stable API, additions belong in a minor release. Renames, removals,
changed argument meanings or incompatible return shapes require a major
release. Before removal, retain a callable deprecated form for at least one
minor release, with a `DeprecationWarning` naming the fully qualified symbol,
replacement and removal version. Document numerical bug fixes in the changelog,
including changed reference results; do not preserve an incorrect answer merely
to keep a fixture unchanged. Compatible internal refactors and fixes can ship
in patch releases.

The established stable scope includes VAR (except regime-switching and GVAR),
local projections, inference, identification, the Klein solver, volatility,
cycles, cointegration, factor models, KORV GMM, MIDAS, spectral methods,
synthetic control, wavelets, realized volatility and labor-share estimators.
The research surfaces previously excluded from the stability promise remain
experimental: other structural/research models (including HANK and sovereign
extensions), regime VAR/GVAR, causal ML, dynamic programming/VFI, spatial GE,
OccBin, narrative/uncertainty, SMM, Bartik and research data-pipeline builders.
Their changes must still be explicit, tested and documented. Experimental
status is not a claim of independent economic validation.

Private modules and non-exported helpers are implementation details. Teaching
wrappers have separate optional dependencies. Examples are shipped in the wheel
and checked as workflows, but do not acquire a stable estimator API merely by
being examples. Fetchers depend on external provider schemas and are best-effort;
offline fixtures and schema checks document their expected inputs.

## Release evidence

Follow [RELEASING.md](https://github.com/jalonso1979/puremacro/blob/main/RELEASING.md).
Release checks cover the supported Python/OS matrix, public API, synchronized
versions, Python 3.11 syntax and native/Windows typing, the Pyodide import
contract, optional numerical reference suites, and representative installed-wheel
examples. Full notebook execution and live Pyodide smoke tests remain separate
checks with their own recorded results. A successful wheel smoke run is not a
substitute for either.
