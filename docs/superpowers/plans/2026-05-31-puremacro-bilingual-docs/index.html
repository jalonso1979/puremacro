    puremacro bilingual (EN+ES) docs & examples + coverage tooling — Implementation Plan

    For agentic workers: REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. The Spanish content is produced by parallel-workflow batches (Phases 1-3); the controller dispatches each batch, then verifies + commits. Phases 0 and 4 are concrete TDD/config tasks. Steps use checkbox (- [ ]) syntax.

    Goal: Ship a broad Spanish (ES) layer alongside the English docs/examples — README.es.md, docs/es/, 12 ES-narrated notebooks (bilingual playground), a Spanish examples gallery + flagship bilingual docstrings — plus coverage tooling (config + CI job).

    Architecture: Separate Spanish files; English untouched except a one-line language switcher. ES content generated by Drive-safe parallel workflows (agents write only their new ES file, never commit; controller commits per batch + verifies). A file-existence "bilingual parity" test guards completeness.

    Tech Stack: Markdown, jupytext notebooks (tools/build_notebooks.py), pytest, pytest-cov/coverage, GitHub Actions.

    Spec: docs/superpowers/specs/2026-05-31-puremacro-bilingual-docs-design.md Working dir: the package root (pyproject.toml, puremacro/, tests/, notebooks/, docs/).

    Conventions (verified this session): - English files are NOT translated in place; Spanish lives in separate files. The only edit to English docs is an additive 🇬🇧 EN | 🇪🇸 ES switcher line. - Spanish = native academic-register macro Spanish (correct terms: proyección local, restricciones de signo, identificación, volatilidad realizada, incertidumbre, crecimiento en riesgo, descomposición, choque).     Phase 0 — coverage tooling (the "do the tests" item)

    Finding (verified during planning): the pytest-cov "double-import" does NOT reproduce in the supported flow — pytest --cov=puremacro runs clean (full + single-file). The a1_coverage.pth auto-start is gated on COVERAGE_PROCESS_START (unset), so it's inert. The agents only hit the error via their --noconftest workaround. So Phase 0 is: verify, add a deterministic coverage config, add the CI job, and document the --noconftest quirk — NOT a code bugfix.

    Task 0.1: Confirm pytest --cov works + add coverage config

    Files: Modify pyproject.toml (add [tool.coverage.*])

    • [ ] Step 1: Verify the supported flow works (no change yet)

    Run: python3 -m pytest tests/test_korv_gmm_coverage.py --cov=puremacro.korv_gmm -q Expected: PASS + a coverage table (≈74%). Run: python3 -m pytest tests/test_local_http_post.py --cov=puremacro._http -q → PASS + table. (Confirms single-file --cov works through the conftest.)

    • [ ] Step 2: Add a deterministic coverage config to pyproject.toml (after [tool.mypy]):

    Task 4.1: Bilingual-parity test (TDD)

    Files: Create tests/test_bilingual_docs.py

    • [ ] Step 1: Write the test (it will pass once Phases 1-2 are committed): 

      # tests/test_bilingual_docs.py
"""Parity: every English user-facing doc/notebook has a Spanish counterpart."""
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]  # package root


def test_readme_es_exists():
    assert (ROOT / "README.es.md").is_file()


def test_user_docs_have_spanish():
    en_docs = ["credentials", "cache_db", "connector_health", "signal_contract",
               "examples_gallery", "1.0_path", "lexicon_review"]
    missing = [d for d in en_docs if not (ROOT / "docs" / "es" / f"{d}.md").is_file()]
    assert not missing, f"missing docs/es/: {missing}"


def test_notebooks_have_spanish():
    nb = ROOT / "notebooks"
    en = [p for p in nb.glob("*.py") if not p.name.startswith("_")
          and not p.stem.endswith("_es")]
    missing = [p.name for p in en if not (nb / f"{p.stem}_es.py").is_file()]
    assert not missing, f"notebooks lacking _es sibling: {missing}"


def test_switcher_in_english_readme():
    txt = (ROOT / "README.md").read_text(encoding="utf-8")
    assert "Español" in txt[:600], "language switcher missing from README.md top"
