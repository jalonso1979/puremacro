# Hoja de ruta y compatibilidad de la API

PureMacro ya superó la versión 1.0. Esta página sustituye la antigua lista previa
a 1.0 y conserva su URL para los enlaces existentes. Al 2026-10-29, **6.0.1 es
la versión publicada** y **6.1.0 está en desarrollo**. Las etiquetas 5.8.0, 5.9.0
y 6.0.0 no se publicaron en PyPI. Consulte el
[registro de cambios](https://github.com/jalonso1979/puremacro/blob/main/CHANGELOG.md)
y `puremacro.__version__` al reproducir resultados.

## Prioridades de desarrollo

1. El código de desarrollo 6.1 incluye el motor GMM, el núcleo de valoración de
   activos, el bloque fiscal soberano y los informes bilingües. Las comprobaciones
   de publicación cubren las plataformas soportadas, el tipado de Python 3.11 y
   los ejemplos desde un wheel instalado.
2. El **equilibrio general** HANK publicado de un activo ya pasa comprobaciones
   independientes no lineales y de malla/horizonte; véase la [referencia](hank_equilibrium.md).
   Extender esta base a la incidencia sobre hogares y flujos con datos observados.
3. El estudio de malla del Arellano básico de corto plazo está completo. Ahora
   se comprueban independientemente las ecuaciones en mallas pequeñas de deuda
   de largo plazo, reestructuración y el planificador ilustrativo con colateral;
   véase [la validación de extensiones](sovereign_extensions_validation.md).
   Los escenarios sensibles de reingreso y persistencia aún necesitan evidencia
   separada de malla. Los momentos publicados de las extensiones y un modelo
   competitivo completo con colateral siguen fuera del alcance validado.
4. Hecho en el código de desarrollo 6.1: verificar y explicar independientemente
   la VE positiva del consumo del informe arancelario, incluidos inversión, otros
   usos finales y recursos. Vea [la validación](tariff_validation.md).

Los hitos de desarrollo completados no validan todos los modelos o calibraciones
ni prometen una publicación concreta. La [guía de fiabilidad](research_reliability.md) distingue
replicaciones, comprobaciones internas y demostraciones.

## Política de compatibilidad

`tests/fixtures/public_api_snapshot.json` registra las exportaciones públicas y
los campos de las clases de resultados. La compuerta 3 exige una actualización
intencional y revisada cuando cambia esa superficie. Comprueba nombres, no
corrección numérica, firmas ni compatibilidad semántica; estas requieren pruebas
y revisión.

En la API estable, las adiciones corresponden a versiones menores. Renombrar,
eliminar o cambiar el significado de argumentos o la forma de retorno requiere
una versión mayor. Antes de eliminar una forma antigua, manténgala invocable al
menos una versión menor, con `DeprecationWarning` que indique el símbolo completo,
el reemplazo y la versión de eliminación. Documente las correcciones numéricas
y sus cambios en resultados de referencia: una respuesta incorrecta no debe
conservarse solo para mantener un fixture. Las refactorizaciones compatibles y
correcciones pueden publicarse como parches.

El alcance estable incluye VAR (salvo regímenes y GVAR), proyecciones locales,
inferencia, identificación, Klein, volatilidad, ciclos, cointegración, factores,
GMM de KORV, MIDAS, métodos espectrales, control sintético, wavelets, volatilidad
realizada y participación laboral. Siguen siendo experimentales las superficies
antes excluidas: otros modelos estructurales y de investigación (incluidos HANK
y extensiones soberanas), VAR de regímenes/GVAR, ML causal, programación dinámica/
VFI, equilibrio espacial, OccBin, narrativa/incertidumbre, SMM, Bartik y
constructores de datos de investigación. Sus cambios también deben ser explícitos,
probados y documentados. El carácter experimental no acredita validación económica
independiente.

Los módulos privados y auxiliares no exportados son detalles de implementación.
Las envolturas docentes tienen dependencias opcionales. Los ejemplos sí se incluyen
en el wheel y se comprueban como flujos de trabajo, sin adquirir por ello una API
estable de estimación. Los fetchers dependen de esquemas externos y funcionan bajo
el criterio de mejor esfuerzo; fixtures y comprobaciones de esquema documentan
las entradas esperadas.

## Evidencia para publicar

Siga [RELEASING.md](https://github.com/jalonso1979/puremacro/blob/main/RELEASING.md).
Las comprobaciones cubren Python y sistemas soportados, API pública, versiones,
sintaxis de Python 3.11 y tipado nativo/Windows, contrato de importación Pyodide,
referencias numéricas opcionales y ejemplos representativos desde un wheel
instalado. La ejecución completa de cuadernos y las pruebas reales de Pyodide
siguen siendo comprobaciones separadas con evidencia propia. La prueba del wheel
no las sustituye.
