## 2024-10-23 - Keyboard navigation for custom D3 charts
**Learning:** Adding keyboard navigation to complex D3-rendered SVG elements (like a scatter plot with Voronoi hover areas) is straightforward by placing `.attr("tabindex", 0)` on the full-area bounding `<rect>` that usually captures pointer events. Keyboard events (`keydown`, `focus`, `blur`) can then be attached directly to this rect, and state (like the currently focused index `curK`) can be maintained within the chart's closure.
**Action:** When working on interactive visualizations without native focusable elements (like individual SVG circles or paths), add an invisible, focusable SVG `<rect>` that acts as the keyboard proxy and dispatches state updates based on arrow keys.
## 2024-10-23 - Resolving CI regressions
**Learning:** Changes to the number of tracked components (like adding a new notebook, `69_reproducible_studies.py`) can break strict testing assertions designed to ensure repository hygiene. For example, tests enforcing that the number of showcase notebooks match ranges documented in `README.md` and `README.es.md`. Likewise, static analysis tools verifying the absence of residual statements like `plt.show()` in code logic can fail when new files bypass those restrictions.
**Action:** Always run relevant codebase hygiene tests or full suite CI locally after performing edits, even those outside of the direct target files. In Python-based workflows testing `matplotlib` hygiene, avoid leaving un-commented `plt.show()` calls in example or module scripts if the project dictates strict programmatic styling configurations or strictly enforces them in tests.
