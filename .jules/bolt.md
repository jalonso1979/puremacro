## 2026-08-31 - Memory reallocation in numpy simulation loops
**Learning:** Calling `np.concatenate` to manage rolling history buffers in tight simulation loops (like for Generalized IRF trajectories across `H` steps and `M` parallel histories) is a significant bottleneck due to constant reallocation and copying of the whole buffer, even though the arrays are relatively small per iteration. Pre-allocating the full future length works but increases peak memory. Simply slicing and re-assigning inplace (`buf[:, :-1] = buf[:, 1:]` and `buf[:, -1] = y`) gives ~15% speedup vs `np.concatenate` without the overhead and memory jump of full pre-allocation.
**Action:** When shifting time buffers inplace in high-throughput hot loops with Numpy, use slicing and inplace assignment instead of `np.concatenate` to minimize reallocation.

## 2026-08-31 - Pandas loop optimization complexities with coercion
**Learning:** Replacing `df.iterrows()` with vectorization when inserting to SQLite requires extreme care around native types and error handling. `sqlite3.executemany()` does not accept numpy numeric types (e.g., `np.float64`) or numpy `NaN` mapped to float arrays. Furthermore, using `pd.to_numeric(errors="coerce")` on mixed data drops the original difference between pre-existing NaNs and strings that failed parsing. To perfectly match original loop semantics which skipped failed parses but kept valid NaNs (as `None`), you must use boolean masking like `invalid_val = (~pd.isna(df['val'])) & coerced_vals.isna()` and explicitly cast array elements back to Python standard types `[float(x) if not pd.isna(x) else None for x in arr]`.
**Action:** When vectorizing database ingestion paths, use boolean masks to preserve precise row-skipping logic for invalid coercions without discarding legitimate `NaN` inputs, and safely cast the final array slice into native Python list comprehensions.
