## 2026-08-31 - Memory reallocation in numpy simulation loops
**Learning:** Calling `np.concatenate` to manage rolling history buffers in tight simulation loops (like for Generalized IRF trajectories across `H` steps and `M` parallel histories) is a significant bottleneck due to constant reallocation and copying of the whole buffer, even though the arrays are relatively small per iteration. Pre-allocating the full future length works but increases peak memory. Simply slicing and re-assigning inplace (`buf[:, :-1] = buf[:, 1:]` and `buf[:, -1] = y`) gives ~15% speedup vs `np.concatenate` without the overhead and memory jump of full pre-allocation.
**Action:** When shifting time buffers inplace in high-throughput hot loops with Numpy, use slicing and inplace assignment instead of `np.concatenate` to minimize reallocation.

## 2026-09-20 - Vectorizing Pandas loop expansions
**Learning:** `iterrows()` is incredibly slow, especially when applying nested logic for metadata assignment across thousands of API-fetched records. For cross-sectional time-series repetition (like expanding annual data to quarterly), applying `DataFrame.index.repeat(N)` along with `np.tile()` for cyclic column values provides an order of magnitude speedup over iterating rows and appending to a python list. Similarly, iterating to cast types and build dicts from API JSON payloads is far slower than loading directly via `pd.DataFrame.from_records()` and applying vectorized `pd.to_numeric` and Series `map()` calls.
**Action:** When mapping or expanding panel data frames in Python, always prefer `pd.DataFrame.from_records()` for ingestion and `np.repeat`/`np.tile`/`pd.Series.map` for transformation over manual Python-level loops (`iterrows()` or `itertuples()`).
