## 2026-08-31 - Memory reallocation in numpy simulation loops
**Learning:** Calling `np.concatenate` to manage rolling history buffers in tight simulation loops (like for Generalized IRF trajectories across `H` steps and `M` parallel histories) is a significant bottleneck due to constant reallocation and copying of the whole buffer, even though the arrays are relatively small per iteration. Pre-allocating the full future length works but increases peak memory. Simply slicing and re-assigning inplace (`buf[:, :-1] = buf[:, 1:]` and `buf[:, -1] = y`) gives ~15% speedup vs `np.concatenate` without the overhead and memory jump of full pre-allocation.
**Action:** When shifting time buffers inplace in high-throughput hot loops with Numpy, use slicing and inplace assignment instead of `np.concatenate` to minimize reallocation.
## 2026-08-31 - Pandas Vectorized Row Operations & Coercion
**Learning:** `pd.DataFrame.iterrows()` is known to be slow for database bulk insertion loops compared to `itertuples()` or `to_dict('records')`. However, safely vectorizing such operations requires care to maintain original error handling. Using `pd.to_numeric` and `pd.to_datetime` with `errors='coerce'` converts unparseable values to `NaN`/`NaT`, which conflates them with native missing values (e.g. SQL `NULL`s vs bad strings that should be dropped). Comparing `df['value'].isna()` before and after coercion into masks successfully differentiates the two groups in an efficient vectorized way.
**Action:** When vectorizing `iterrows()` loops involving parsing errors, preserve existing skipping logic by keeping track of pre-coercion and post-coercion `NaN` masks, and use `np.where(isna(), None, val)` to explicitly map Python missing values to standard `None` to prevent `sqlite3` from throwing type errors on `numpy.nan` or `numpy.float64`.
