## 2024-05-18 - Avoid full matrix inversion with np.linalg.solve
**Learning:** For a complex problem with repeated matrix inversions followed by matrix multiplication like `Psi_w = np.linalg.inv(I_minus_A)` and `PS_w = Psi_w @ Sigma`, we can optimize this by using `np.linalg.solve(I_minus_A, Sigma)`. Even if `Psi_w` is also required for the calculation, using `np.linalg.solve(I_minus_A, np.eye(n))` might be numerically preferable to `inv()`, but computing both with `solve` remains mathematically identical, avoids `inv`, and opens paths for fully vectorizing the logic without maintaining inverse states explicitly. Wait, our benchmark showed computing both via `solve` was practically as fast. If we want maximum performance, we can rewrite the math to avoid computing `Psi_w` altogether or vectorize over `w_grid`, but a direct translation (which is asked for) simply means solving for both.
**Action:** When translating `inv(A) @ B` patterns, directly use `np.linalg.solve(A, B)`. If both the full inverse and the product are used, consider if the math can be simplified (e.g. `(A^-1 B) @ (A^-1)^T`) before just defaulting to two `solve()` calls.
