## 2026-08-31 - Memory reallocation in numpy simulation loops
**Learning:** Calling `np.concatenate` to manage rolling history buffers in tight simulation loops (like for Generalized IRF trajectories across `H` steps and `M` parallel histories) is a significant bottleneck due to constant reallocation and copying of the whole buffer, even though the arrays are relatively small per iteration. Pre-allocating the full future length works but increases peak memory. Simply slicing and re-assigning inplace (`buf[:, :-1] = buf[:, 1:]` and `buf[:, -1] = y`) gives ~15% speedup vs `np.concatenate` without the overhead and memory jump of full pre-allocation.
**Action:** When shifting time buffers inplace in high-throughput hot loops with Numpy, use slicing and inplace assignment instead of `np.concatenate` to minimize reallocation.

## 2024-05-18 - Preserving semantics when vectorizing pandas loops
**Learning:** Replacing `.iterrows()` with vectorized `.to_numeric()` or `.to_datetime()` using `errors="coerce"` turns all unparseable values into `NaN`. If the original code skipped rows with bad values (e.g., via try/except) but kept rows with native `NaN`s, the naive vectorization will unintentionally alter behavior by treating both cases identically as missing data. Additionally, pandas `float64` columns cannot simply have `None` assigned via `.where()` for SQLite NULL compatibility; doing so converts `None` back to `NaN`.
**Action:** When vectorizing `iterrows()` loops, use boolean masks to differentiate originally missing data from coercion failures (e.g., `original_isna = pd.isna(df['val']); coerced = pd.to_numeric(df['val'], errors='coerce'); new_isna = pd.isna(coerced); keep = original_isna | ~new_isna`). To insert SQLite `NULL`s, explicitly cast the column first: `df['col'] = df['col'].astype(object).where(pd.notna(df['col']), None)`.
