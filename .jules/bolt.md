## 2026-08-31 - Memory reallocation in numpy simulation loops
**Learning:** Calling `np.concatenate` to manage rolling history buffers in tight simulation loops (like for Generalized IRF trajectories across `H` steps and `M` parallel histories) is a significant bottleneck due to constant reallocation and copying of the whole buffer, even though the arrays are relatively small per iteration. Pre-allocating the full future length works but increases peak memory. Simply slicing and re-assigning inplace (`buf[:, :-1] = buf[:, 1:]` and `buf[:, -1] = y`) gives ~15% speedup vs `np.concatenate` without the overhead and memory jump of full pre-allocation.
**Action:** When shifting time buffers inplace in high-throughput hot loops with Numpy, use slicing and inplace assignment instead of `np.concatenate` to minimize reallocation.

## 2024-09-25 - Pandas Vectorization with Coercion for Database Inserts
**Learning:** When replacing `.iterrows()` with vectorized pandas operations for SQLite insertion, you must explicitly enforce error-handling parity. Using `pd.to_numeric` and `pd.to_datetime` with `errors="coerce"` will turn both native missing values *and* unparseable garbage into `NaN`/`NaT`. To mimic original `.iterrows()` try/except logic (which might accept native NaNs but drop unparseable rows), use a boolean mask comparing `.isna()` on the pre-coerced column to the post-coerced column. Also, ensure the final generated structure converts numpy numeric types (`np.nan`) to Python primitives (`None`, `float`) via a list comprehension or generator before using `sqlite3.executemany()`.
**Action:** Always reconstruct native parsing/dropping boolean logic using inverse `.isna()` masks when vectorizing `try/except` string coercion blocks in Pandas.
